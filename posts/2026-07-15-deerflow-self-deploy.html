DeerFlow 2.0 本地部署指南

2026.07.15

本文浏览 ·· 次 · 访客 ·· 人

DeerFlow 是字节跳动开源的超级智能体框架，可以调用模型、搜索网页、读取文件、生成报告，并把复杂任务拆给多个子智能体执行。

这篇教程的目标很简单：把 DeerFlow 安装在你自己的电脑上，使用你自己的模型和 API Key。这样不会占用别人的服务器资源，你的对话和文件也保存在自己的设备上。

适合谁：想体验本地 AI 智能体，并且愿意按步骤执行几条终端命令的人。

预计时间：网络正常时约 15—30 分钟；首次下载依赖和沙箱镜像可能更久。

先确认你的电脑是否合适

  • macOS 或 Linux 最合适；Windows 建议使用 Git Bash。
  • 最低建议：4 核 CPU、8 GB 内存、20 GB 可用空间。
  • 更舒服的配置：8 核 CPU、16 GB 内存。
  • 如果还要在本机运行 Ollama 大模型，需要额外的内存或显存。

方法一：把安装任务交给编程智能体

这是最省事的方法。打开 Codex、Claude Code、Cursor 或其他可以操作终端的编程智能体，把下面整句话发给它：

Help me clone DeerFlow if needed, then bootstrap it for local development by following https://raw.githubusercontent.com/bytedance/deer-flow/main/Install.md

这是 DeerFlow 官方提供的一句话安装方式。智能体会检查环境、克隆项目并告诉你还缺什么配置。模型 Key 需要你自己提供，但不要直接把完整 Key 发到公开聊天或截图里。

方法二：手动安装

1. 下载 DeerFlow

打开终端，依次执行：

git clone https://github.com/bytedance/deer-flow.git
cd deer-flow

2. 运行配置向导

make setup

向导会让你选择模型、搜索工具和执行权限。第一次使用可以按下面配置：

  • 模型：选择你已有 Key 的服务商，例如 DeepSeek、MiniMax 或 Gemini；也可以选择本地 Ollama。
  • 网页搜索：DuckDuckGo 不需要 Key。
  • 网页读取：Jina AI Reader 不需要 Key。
  • 执行模式：个人电脑可以先选 Local sandbox。
  • Bash 命令：新手建议关闭。
  • 文件写入：新手建议关闭，需要时再开启。
  • 即时通信渠道：可以先不选。
每个人都应该填写自己的 API Key。不要使用网上分享的 Key，也不要把 Key 提交到 GitHub。

3. 检查安装状态

make doctor

如果有缺失依赖，按照终端给出的提示安装。处理完后再次运行 make doctor，直到关键检查通过。

4. 启动 DeerFlow

make dev

启动完成后，在浏览器打开：

http://localhost:2026/

首次进入会要求创建管理员账号。这个账号只属于你当前安装的 DeerFlow。

终端需要一直开着吗？

使用 make dev 时，终端窗口需要保持运行。想让它在后台运行，可以先停止前台服务，再执行：

make stop
make dev-daemon

常用管理命令：

make stop          # 停止服务
make dev-daemon    # 后台启动开发模式
make doctor        # 检查配置和依赖

后台运行不等于开机自启；电脑重启后通常需要重新启动服务。长期使用可以再配置系统服务，或者改用 Docker 生产部署。

接入本地 Ollama 模型

  1. 先安装并启动 Ollama。
  2. 使用 ollama list 确认本机已经下载的模型。
  3. 重新运行 make setup，选择 Ollama。
  4. 选择你本机真实存在的模型名称。
ollama list
make setup
make doctor
make dev

本地模型不会产生云端模型调用费，但会占用电脑的 CPU、GPU、内存和磁盘。模型越大，速度和硬件要求越高。

如果想长期部署在服务器

多人共享或长期运行时，官方更推荐 Linux + Docker。完成 make setup 后，可以使用：

make up      # 构建并启动生产服务
make down    # 停止生产服务

共享部署还需要 HTTPS、强认证、容器沙箱、访问限制和调用额度控制。不要把没有保护的 2026 端口直接暴露到公网。

常见问题

页面打不开

make doctor
make stop
make dev

确认终端中没有报错，并检查 http://localhost:2026/ 是否可以访问。

模型调用失败

  • 检查 API Key 是否正确、是否有余额。
  • 确认模型名称和服务商支持的名称完全一致。
  • 本地模型需要确认 Ollama 正在运行。

安装问题无法解决

make support-bundle

它会生成经过脱敏的诊断摘要，方便到 DeerFlow GitHub Issues 提问。发送前仍建议自己检查一遍，确认不包含隐私信息。

安全提醒

  • API Key 只放在自己的 .env 中，不要提交到 GitHub。
  • 不确定工具行为时，保持 Bash 和文件写入关闭。
  • 本地沙箱不是严格的安全隔离边界。
  • 不要随意运行陌生人提供的脚本、技能或 MCP 服务。
  • 不要把 DeerFlow 端口直接映射到公网。

官方资料
